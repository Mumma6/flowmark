title: Quickstart
description: Record an existing job and open its first run in Flowmark Studio.

Start with one process your application already runs, such as an invoice import.
Each invocation records a run with its timing and reported execution status.
Studio lets you open the run and see what the application reported.

## Record an invoice import in Next.js

Create a Studio project and save its server write key. Install the SDK:

```bash
npm i @flowmarkdev/node
```

Set `FLOWMARK_API_KEY` in your server environment. For a local or staging
Flowmark API, set `FLOWMARK_API_URL` to its origin. Keep the key out of
`NEXT_PUBLIC_*` variables and client code.

Create one shared server-only client:

```ts
// lib/flowmark.ts
import { createFlowmark } from "@flowmarkdev/node/next"

export const flowmark = createFlowmark()
```

In an existing Route Handler or Server Action on the Node.js runtime, import that
client and wrap your application's existing function. Keep the handler's usual
authorization, validation and response behavior.

```ts
const result = await flowmark.workflow("invoice.import", () => importInvoices())
```

The callback reports completion on return and records unexpected failures while
preserving the original error. Next.js handles delivery after the request.
For a standalone script or worker, use the [Node.js guide](/docs/nodejs) and
its process-owned delivery steps.

## Open the recorded run

Use a safe existing application action or test that runs the instrumented path.
In Studio, select the project that owns the write key. Under **Setup instructions**,
select **Check for a run**, then **Open recorded run** when a run appears.
You can also open it from the run list in **Explore**.

If the job cannot run safely now, open Studio and return after normal traffic.
If an expected run still does not appear, verify the project write key, API origin
and [SDK delivery diagnostics](/docs/troubleshooting). Studio distinguishes a waiting
project from a failed read.

The basic callback reports timing and execution status. To see how many invoices
were imported or skipped, add the [reported result](/docs/reference/completion)
your application already knows. In Studio, **Reported results** shows those values
and **Timeline** shows any milestones or operations you add.

## Use a coding agent

Choose **Set up with a coding agent** in Studio and copy the setup prompt into a
client that can inspect your application repository. Keep the write key in the
server environment. Review the proposed application change before it is applied.

After evidence arrives, you can separately [connect a read-only MCP client](/docs/mcp)
to investigate the recorded run.
