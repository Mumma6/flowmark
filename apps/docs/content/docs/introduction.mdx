**Understand what your software actually does.**

Flowmark is an open-source process-intelligence platform. Instrument the processes
your application already runs, collect execution evidence, and understand technical
and reported business outcomes over time.

A completed import can still have skipped records. A failed order can already
have captured a payment. A completed request can still have an outstanding
confirmation. Flowmark keeps those observations distinct and lets you inspect
the evidence behind them. Your application owns execution, scheduling and retries.

## Start with one process

```ts
const run = flowmark.workflow("invoice.import", { properties: { batchId } })
run.step("source-loaded", { properties: { count: 1000 } })
run.done({ outcome: "partial", result: { imported: 988, skipped: 12 } })
```

This is an instrumentation sketch. The [quickstart](/docs/sdk) shows shared-client
setup, real work, failure handling and delivery. Configure a server write key
outside browser bundles and use an API that accepts the markers you enable.

```bash
npm i @flowmarkdev/node
```

## What you can use today

- **Record executions:** workflows, milestones, overlapping operations, handled
  errors, absolute progress and context amendments.
- **Describe business evidence:** explicit final outcomes/results and non-final
  reports. Typed definitions provide reusable instrumentation handles.
- **Follow related work:** continue a run across requests, or explicitly link
  distinct runs and application-owned attempts.
- **Inspect confirmations:** declare an expectation and report its resolution or
  cancellation. Deadlines are evaluated on read; there is no background alerting.
- **Investigate history:** search enabled references, filter runs, compare peers
  and examine timelines in Studio.
- **Analyze reported outcomes:** declared fields, revisions, coverage, reasons,
  weighted ratios and release comparisons, with links to the matching runs.

SDK marker availability depends on the deployed accepting server. Missing values
are not zero; completion is not verified business success. Browser reports remain
untrusted. See [delivery](/docs/delivery) and [metric meanings](/docs/concepts/insights).

## Product 1.0 direction

Flowmark is one platform with three dimensions:

- **Platform:** the SDK, evidence, contextual relationships, analysis and
  programmable access.
- **Studio:** the workspace for exploring processes, business references,
  comparisons and supporting evidence.
- **Everywhere:** agents, embedded views and custom tools.

Studio is the current web interface. It opens in Explore and keeps the same
filters when you inspect a run. The API includes six read-only MCP tools for an
authorized project when the deployment enables agent access. A disabled
deployment does not offer a working MCP connection. Saved investigations, a
portable agent interface and a Studio assistant are not built. Setup guidance
and a copied run summary still support a manual handoff. Engineering, Product,
Customer Success, Sales and Operations use the same recorded evidence.
