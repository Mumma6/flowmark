**Flowmark is application memory for AI-native software teams.** Your agent reads the code to understand what could happen. Flowmark records what the application reported when it ran, including partial results, retries and later confirmations.

## Start with the change

In a synthetic example, two booking callbacks arrive for the same booking. One repeats a change and the other moves the booking again. Seeing both cases can keep an agent from suppressing a legitimate update. Source, execution and provider acknowledgments each answer different questions.

## Use the current agent interface

Give the coding agent [read-only project access](/docs/mcp). It can use the existing workflow discovery and bounded run reads to find cases, compare peers and inspect the observations that support a decision. If the application needs an observation, the agent can use the [SDK integration guide](/docs/sdk) and verify the emitted result. The application continues to own its work and retries.

The planned change-facing interface will accept a ticket, diff, file or symbol directly. Managed repository installation, autonomous repair and release-specific coverage are in development planning. Today's tools and access steps are listed in the [MCP guide](/docs/mcp).

## Human controls

Humans define intent, connect and authorize access, set collection policy, protect secrets and merge changes. Studio exposes [project access](/docs/project-access), [account and data controls](/docs/account-data) and an [execution inspector](/docs/concepts/dashboard). A completed run with skipped items is still partial work. Missing telemetry leaves the result unknown.
