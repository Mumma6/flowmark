---
title: Connect Cursor with MCP
description: Give Cursor read access to Flowmark evidence and investigate executions, failures and reported outcomes.
---

MCP lets Cursor read Flowmark evidence alongside your application code. Use it to
investigate executions, failures and reported business outcomes. Cursor is the
recommended MCP client; it has been verified against real application data in Staging.

**SDK instrumentation collects evidence. MCP reads that evidence.** The
[SDK quickstart](/docs/sdk) helps you install and instrument an application with
your coding agent or manually, without MCP. Connecting MCP does not install the SDK or modify
your repository. Flowmark does not execute, schedule or retry application work.

## 1. Choose a project

Sign in to Studio and select the project whose evidence you want to investigate.
If your application is not reporting yet, complete the [SDK quickstart](/docs/sdk)
to see a useful first execution. You can also connect to an empty project; the
connection check will return an empty process list.

## 2. Add Flowmark to Cursor

Open **Connect** in Studio. Copy the
configuration shown for that environment into your repository's `.cursor/mcp.json`.
Create the file if needed; merge with any existing `mcpServers` entries.

The configuration has this shape. Replace the example URL with the endpoint
shown in Studio:

```json
{
  "mcpServers": {
    "flowmark": {
      "url": "https://YOUR-FLOWMARK-API/mcp",
      "auth": {
        "CLIENT_ID": "flowmark-cursor",
        "scopes": ["openid", "offline_access", "flowmark:read"]
      }
    }
  }
}
```

Open Cursor Settings → Tools & MCP, enable **flowmark**, then choose **Connect**
or **Sign in** when prompted. Labels can vary by Cursor version. See
[Cursor's MCP documentation](https://cursor.com/docs/mcp) for configuration locations.

If Studio cannot confirm the endpoint, retry its connection check. You can
continue exploring evidence in Studio while the MCP connection is unavailable.

## 3. Sign in and approve your project

Cursor opens Flowmark in your browser. Sign in with your Flowmark account, select
the project you created and choose **Allow read access**. Return to Cursor.

Your connection can read only the projects you approve, within your existing
permissions. It stays connected between sessions until expiry or revocation.
Your application write key is separate and is never needed for this sign-in.

## 4. Check read access

Copy the project-specific connection-check prompt from Studio into Cursor. It
asks Cursor to call `get_connection`, then `list_workflows` for that project.
Check that **both tool calls succeed** and name the intended project.

An empty process list is expected before you instrument anything. A copied
configuration or Studio's **Connection authenticated** status alone does not
verify a successful project read.

## 5. Investigate your evidence

In Connect, expand **Investigate with Cursor** and copy a starter question.
Ask Cursor to explain an execution, investigate a failure code or compare reported
business outcomes. The tools read the projects you approved and return links to
supporting Studio evidence.

Start with `get_connection` to confirm the project and available tools. If you
don't know the process name, use `list_workflows`. Run `find_runs` for a short
UTC window and pass its returned run ID to `get_run`. Read the summary and the
page relevant to your question. Follow a cursor only if you need more evidence.

Ask the agent to cite the recorded run and any returned Studio link. Keep
recorded observations, inferences from source code and recommendations
separate. You can investigate in Cursor once the grant works. Studio is
available for visual inspection or when the MCP read is unavailable.

## Explore your first evidence

In Studio, select the process in **Explore** to see its execution history. Open
an execution: **Outcome** shows the application-reported result; **Timeline**
shows milestones, operations and failures. Ask Cursor to explain one execution
with the supporting Flowmark evidence.

Completion is a report, not proof every record succeeded. Missing terminal
telemetry proves neither activity nor failure.

## Manage the connection

In **Connect**, expand **Manage connections and project access** to inspect or
revoke your connections. To change approved projects, revoke and connect again.
Signing out of Studio does not revoke Cursor access. If a revocation response is
unclear, refresh connection state before trying again.

## Troubleshooting

- **Sign-in fails:** confirm the copied configuration includes `auth.CLIENT_ID`
  and all three scopes. Do not add a client secret or ingestion key.
- **Project missing or denied:** check the Flowmark account, select the correct
  Studio project, then reconnect and approve it. A new write key will not fix
  MCP permissions.
- **No processes yet:** a successful empty `list_workflows` response means read
  access works. Instrument and run your application next.
- **No execution after running:** confirm the server write key and API origin
  match this project and environment; check [SDK delivery](/docs/delivery) and
  [troubleshooting](/docs/troubleshooting).
- **Expired or revoked:** reconnect from Cursor and approve the project again.

## Advanced connection details

Flowmark uses Streamable HTTP with a registered public OAuth client. Dynamic
client registration stays off. Cursor desktop uses
`http://localhost:8787/callback`; Cursor on the web uses
`https://www.cursor.com/agents/mcp/oauth/callback`. Custom-scheme callbacks are
rejected. The configuration does not require a client secret.

Cursor is the primary verified MCP connection. The Staging verification covers real
MCP tool calls against application data; it does not certify every Cursor
version, surface, or Flowmark deployment. Other clients are outside this setup
guide. MCP Apps rendering has its own
[reference-host limits](/docs/portable-evidence).

### Available read tools

| Tool                    | Use                                                                            |
| ----------------------- | ------------------------------------------------------------------------------ |
| `get_connection`        | Check available project scope and investigation tools.                         |
| `list_workflows`        | Discover processes and their recorded meaning.                                 |
| `find_runs`             | Find executions in an explicit UTC start window of at most 31 days.            |
| `get_run`               | Read a summary and a page of events, operations, related runs or expectations. |
| `compare_run`           | Compare one execution with a bounded peer selection.                           |
| `get_workflow_insights` | Read period comparisons or declared business-result insights.                  |

Results are bounded pages. Keep the same project and query when using a returned
cursor. Business readers receive only permitted projections. See
[project permissions](/docs/project-access) and the
[MCP adapter contract](https://github.com/Mumma6/flowmark/blob/staging/packages/mcp/README.md)
for the detailed transport and security boundaries.
